1. FEAT_FGT 硬件接口

FEAT_FGT 提供 EL0 SVC 指令的硬件重定向：应用执行 SVC 时，PC 直接跳转到 VBAR_EL0_FDT 注册的入口，不经过 EL0→EL1 异常向量表。

系统寄存器

寄存器编码功能
VBAR_EL0_FDTS3_3_C11_C1_0SVC 重定向入口地址（per-process）。应用 SVC 时 PC 跳转到此。
ELR_EL0标准 ELRSVC 指令下一条地址（SVC+4）。Handler 执行 ERET 时恢复 PC。
SPSR_EL0标准 SPSRSVC 执行时的 PSTATE。ERET 时恢复。
Tindex_EL0-线程索引，handler 快速定位 per-thread 结构。
VBAR_EL0_FDT 访问方式（汇编）：
MSR S3_3_C11_C1_0, Xn — 写入入口地址
MRS Xn, S3_3_C11_C1_0 — 读取当前入口

内核 prctl 接口

调用功能
prctl(71, 1)开启 FEAT_FGT 快速跳转功能
prctl(71, 0)关闭 FEAT_FGT 快速跳转功能
使能粒度（内核语义）：VBAR_EL0_FDT 写入与 prctl(71, 1/0) 使能均按 进程 粒度生效。同一进程内所有线程共享同一重定向入口与使能状态。进程 fork 出的子进程拥有独立的 VBAR_EL0_FDT 与使能状态，需在子进程中重新配置。

行为特征

🔀 SVC 重定向

应用 SVC → PC = VBAR_EL0_FDT。寄存器内容（X0-X5 参数、X8 sysno）原样保留。无 EL0→EL1 异常。

🔒 嵌套 SVC 保护

进入 handler 时硬件自动清除 FEAT_FGT 使能位。Handler 内 SVC 正常走 EL0→EL1→seccomp，不递归。

📋 Per-Process 使能

VBAR_EL0_FDT 与 prctl(71) 均为进程粒度，进程内所有线程共享同一入口。

↩️ ERET 返回

Handler 通过 ERET 返回：PC ← ELR_EL0，PSTATE ← SPSR_EL0。无 sigreturn。

2. 当前 Systrap Syscall 路径

应用 SVC → EL0→EL1 异常 → seccomp BPF 过滤 → SIGSYS 信号投递（内核构建 ucontext：31 regs + fpsimd + siginfo） → __export_sighandler(): 保存 ucontext → switch_context() FUTEX_WAKE sentry get_context() 等待处理 → sentry 处理 syscall → restore_state() → sigreturn → 应用恢复执行

本设计的目标：在现有路径前端插入 FEAT_FGT 跳转层，改造 SVC 指令的跳转行为，使其先进入 EL0 handler 再转发给内核。现有 seccomp+SIGSYS 处理逻辑完全复用。

3. 使能机制（动态开关）

gvisor 提供运行时开关，动态使能/去使能 FEAT_FGT。使能时：配置 VBAR_EL0_FDT 为一个统一的跳转入口，然后全局使能 FEAT_FGT。去使能时：关闭 FEAT_FGT。

3.1 使能流程（per-process）

gvisor 中应用运行在 stub 子进程中。由于内核按进程粒度使能 FEAT_FGT，配置与使能动作必须在 每个 stub 子进程上下文中执行（sentry 进程自身不需要使能）。

每个 stub 子进程初始化:
  ① 写入 SYS_VBAR_EL0_FDT ← fdt_handler 地址（统一跳转入口）
       MSR S3_3_C11_C1_0, Xn
  ② prctl(71, 1)         ← 使能 FEAT_FGT（per-process）
  ③ 打印使能日志

运行中动态关闭（per-process）:
  ① prctl(71, 0)         ← 关闭 FEAT_FGT（per-process）
  ② 打印去使能日志
多进程注意：每个 stub 子进程都需独立执行 ① 写入 + ② 使能。fork 出的新 stub 子进程（如多容器/多 app 场景）会继承父进程状态，但进程独立后需各自配置。若未来支持进程内 fork 应用，子进程需重新注册。

3.2 gvisor 侧开关设计

方式说明
runsc 启动参数新增 --feat-fgt flag，systrap 平台创建每个 stub 子进程时使能
运行时 sysctl新增 sentry 侧 sysctl 节点，运行中可动态 1/0 切换；切换时对所有 stub 子进程广播执行 prctl(71, 1/0)
实现约束：VBAR_EL0_FDT 是 per-process 寄存器，只能在 stub 子进程上下文中写入（sentry 不能直接写其他进程的 VBAR_EL0_FDT）。通过在 stub 汇编中新增配置函数，由 sentry 通过 stub 寄存器调用机制触发执行。

4. 跳转入口（Handler）设计

Handler 是一个 SVC 转发器：保存 X0~X30 到栈 → 按原始系统调用号重新执行 SVC（正常陷入内核，走现有 seccomp+SIGSYS 路径）→ 恢复栈 → ERET 返回应用。

4.1 执行流程

应用 SVC #NR（X0-X5=args, X8=NR） │ ▼ FEAT_FGT 重定向（PC ← VBAR_EL0_FDT, ELR_EL0 ← SVC+4） ┌──────────────────────────────────────┐ │ __export_fdt_handler (EL0): │ │ ① 保存 X0~X30 到栈（不修改寄存器值） │ │ ② 日志计数 +1（共享内存计数器） │ │ ③ SVC #0（X8=原始 NR 原样保留） │ │ └→ EL0→EL1 → seccomp → SIGSYS │ │ → __export_sighandler → sentry│ │ → sigreturn（X0=返回值） │ │ ④ 恢复栈（SP += 保存区大小） │ │ ⑤ ERET（PC ← ELR_EL0, PSTATE ← SPSR_EL0）│ └──────────────────────────────────────┘ │ ▼ 应用恢复执行（SVC 下一条指令，X0=返回值）

4.2 Handler 汇编

TEXT __export_fdt_handler(SB),NOSPLIT,$0
    // ① 保存 X0~X30 到栈（STP 只读寄存器写内存，不改变寄存器值）
    STP X0,  X1,  [SP, #-16]!
    STP X2,  X3,  [SP, #-16]!
    STP X4,  X5,  [SP, #-16]!
    STP X6,  X7,  [SP, #-16]!
    STP X8,  X9,  [SP, #-16]!      // X8 = syscall number
    STP X10, X11, [SP, #-16]!
    STP X12, X13, [SP, #-16]!
    STP X14, X15, [SP, #-16]!
    STP X16, X17, [SP, #-16]!
    STP X18, X19, [SP, #-16]!
    STP X20, X21, [SP, #-16]!
    STP X22, X23, [SP, #-16]!
    STP X24, X25, [SP, #-16]!
    STP X26, X27, [SP, #-16]!
    STP X28, X29, [SP, #-16]!
    STP X30, X30, [SP, #-16]!      // LR

    // ② 日志计数（跳转计数器 +1）
    MOVD $fdt_jump_count_addr(SB), X9
    MOVD (X9), X10
    ADD  $1, X10
    MOVD X10, (X9)

    // ③ 转发：SVC（此时 X0-X5, X8 仍为原始 syscall 参数）
    //    进入 handler 时 FEAT_FGT 已硬件关闭 → 正常 EL0→EL1 → seccomp → SIGSYS
    SVC #0
    //    sigreturn 后返回此处，X0 = syscall 返回值，其余寄存器保持不变

    // ④ 恢复栈（寄存器已是处理后的结果，不从栈覆盖）
    ADD SP, SP, #(16*16)

    // ⑤ ERET：PC ← ELR_EL0, PSTATE ← SPSR_EL0
    ERET()

4.3 关键说明

要点说明
参数透传STP 不修改寄存器值，SVC 时 X0-X5、X8 保持应用原值，syscall 参数零拷贝透传给内核。
寄存器恢复SVC 返回（sigreturn）后寄存器已是处理结果，故 只恢复 SP，不从栈覆盖 X0~X30。
嵌套 SVChandler 内的 SVC 正常走 EL0→EL1→seccomp→SIGSYS，FEAT_FGT 已硬件关闭，不递归。
seccomp 不变转发的 SVC 仍被 seccomp 拦截为 SIGSYS，现有 sighandler 路径无需修改。

5. 日志设计

目标：观察 FEAT_FGT 的使能状态，以及 SVC 指令跳转行为被改变。

5.1 使能/去使能日志（sentry Go 侧）

FEAT_FGT enabled: VBAR_EL0_FDT=0x0000xxxx, prctl(71,1) OK
FEAT_FGT disabled: prctl(71,0) OK

使用 gvisor log.Infof，在使能/去使能时打印入口地址与 prctl 返回值。

5.2 跳转行为日志（handler 侧）

Handler 每跳转一次递增共享内存计数器，sentry 侧读取并周期性打印，以证明 SVC 已被重定向到指定入口：

// stub 地址空间共享内存新增字段:
struct fdt_log {
  uint64_t jump_count;   // SVC 跳转次数
  uint64_t last_sysno;   // 最近一次 syscall number (X8)
};

// handler 侧: 每次跳转 +1, 记录 sysno（见 4.2 节 ②）
// sentry 侧: 周期读取并打印
FEAT_FGT handler: jump_count=1000, last_sysno=172 (getpid)
对比观测：
  • 使能前：应用 SVC 直接 EL0→EL1，日志无 handler 记录
  • 使能后：应用 SVC 跳转到 handler，jump_count 持续增长
  • 通过 jump_count 是否增长，直接验证 SVC 跳转行为已被 FEAT_FGT 改变

8. 风险

#风险项缓解
1 FEAT_FGT 与 seccomp 执行顺序：若 seccomp 先于 FEAT_FGT 拦截，应用 SVC 不跳转 handler 验证阶段观察 jump_count 是否增长；确认硬件翻译 SVC 时先检查 VBAR_EL0_FDT
2 per-process 粒度：每个 stub 子进程都必须独立写入 VBAR_EL0_FDT + prctl(71,1)，多进程/多容器场景配置遗漏 配置逻辑封装在 stub 初始化入口，所有 stub 子进程统一执行；fork 后显式重新注册
3 handler 内 SVC 转发时被信号（SIGCHLD）打断 保留现有 SIGCHLD 处理，futex(FUTEX_WAIT) 可被信号打断
4 每次 syscall 多一次栈保存/恢复（16 对 STP + SP 恢复）开销 本阶段目标是验证跳转行为；性能优化是后续阶段（handler 直接与 sentry 通信）
本阶段定位：先通过 SVC 转发器方案验证 FEAT_FGT 跳转行为被正确改变（日志观测），复用现有 systrap 处理路径，风险最小。性能优化（跳过 seccomp/信号，handler 直连共享内存）作为后续迭代。
